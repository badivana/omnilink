# ONP v1 compact server contract

The byte-level codec is `omnilink/onp.py`, with golden vectors and corruption tests in `tests/test_protocol_reference.py`. The server implements the compact subset of the previously supplied ONP candidate design.

The 20-byte header is magic `ON`, version 1, flags u8, message type u8, codec u8, message ID u32, session ID u32, payload length u32, header CRC16 u16. Integers use big endian. CRC16 is CCITT-FALSE: polynomial 0x1021, initial 0xffff, no reflection or final XOR; `123456789` yields 0x29b1. Flags are RESPONSE=1, ACK_REQUESTED=2, RETRANSMISSION=4. Message IDs are nonzero. A bad native header closes the connection; it is never resynchronized by scanning for magic.

## Authentication

Connect to verified TLS port 7443, or binary WebSocket `/device/onp` through the deployment's HTTPS endpoint. The preauthentication receive limit is 256 decoded bytes and each handshake stage has a ten-second deadline.

HELLO (0x01), session 0, compact payload:

```text
device_id Str8; role u8 (0 device / 1 gateway-child); firmware Str8 <=32;
codec_mask u8; capabilities u32; type_mask u32; max_frame u32;
heartbeat_seconds u16; client_nonce[16]; boot_id[16]
```

Str8 is a one-byte UTF-8 byte length followed by bytes. This implementation requires compact support (codec mask bit 0). Capabilities have bits 0 report/read, 1 write, 2 telemetry, 3 events, 4 time, 5 persistent applied revisions. The type mask has bit `type_id - 1`. Reserved mask bits are rejected. The server caps negotiated frames at 4096 total bytes and heartbeat at 10–120 seconds.

HELLO_ACK (0x02) uses RESPONSE with the HELLO message ID, session 0:

```text
selected_codec u8 (0); capabilities u32; type_mask u32; max_frame u32;
heartbeat_seconds u16; auth_method u8 (1)
```

CHALLENGE (0x04) has a new server message ID, session 0: random nonce[32], validity seconds u16 (10). AUTH_RESPONSE (0x05) echoes the challenge message ID with RESPONSE and session 0: method u8 (1), proof length u16 (32), proof[32].

```text
proof = HMAC-SHA256(device_secret,
    "OmniLink-ONP1-auth\0" || SHA256(HELLO payload) ||
    SHA256(HELLO_ACK payload) || server_nonce)
```

AUTH_OK (0x06) carries the new nonzero session ID in its header, plus server UTC epoch milliseconds u64 and uncertainty milliseconds u32. Subsequent frames must carry that session ID and codec 0. Failure (0x07) is generic and closes the connection. Secrets are never sent directly over ONP. TLS bearer and mTLS authentication methods are not implemented in this release.

## Messages

| Type | Payload / behavior |
|---|---|
| 0x08 PING | Empty; server sends 0x09 PONG with RESPONSE and the same ID |
| 0x10 VWRITE | Server command; key[16], desired revision u32, expiry epoch ms u64, channel u16, typed value |
| 0x12 VSYNC | First channel u16, count u16 (1–16); ACK accepted, then new durable writes for current desired values, subject to manual override |
| 0x13 VREPORT | Sequence u32, observed epoch ms u64, applied key[16], desired revision u32, channel u16, typed value |
| 0x20 TELEMETRY | Sequence u32, observed ms u64, quality u8, count u16; repeated metric Str8 and typed value |
| 0x21 EVENT | Sequence u32, observed ms u64, severity u8, code Str8, detail Str16 |
| 0x60 TIME_REQUEST | Client monotonic milliseconds u64 |
| 0x61 TIME_RESPONSE | Echoed client monotonic ms u64, receive UTC ms u64, send UTC ms u64, uncertainty ms u32; RESPONSE with same ID |
| 0x80 ACK / 0x81 NACK | Key[16], revision u32, status u8 (0 accepted / 1 applied / 2 rejected), error u16 |

Typed value = type u8, byte length u16, encoded bytes. BOOL is exactly one byte 0 or 1; fixed-width scalars follow their type widths; strings are UTF-8; BYTES is opaque; JSON is UTF-8 with no duplicate keys, non-finite numbers, or depth above 8. The API limits individual values to 2048 encoded bytes; a smaller negotiated frame can impose a smaller usable value limit.

Command ACK/NACK frames must use RESPONSE and the original command message ID. Within a connection retries reuse the command key, revision, message ID, and session ID, with RETRANSMISSION set. A reconnect gets a new session/message ID while keeping the same durable command key and revision. Store applied revisions and command outcomes on the device to make retries idempotent. An applied report must match the command's channel/type/value. Server command TTL defaults to 30 seconds; expiry 0 is not generated by this release.

PING and TIME messages are always compact. RPC, config, local schedule, and OTA native extension types remain reserved. VREAD is defined by the design but is not initiated by this release's API; devices report on connection, on change, or periodically. ONP data over WebSocket uses exactly one complete native frame per binary message.

## Serial envelope

`COBS(native frame || CRC16 of complete native frame) || 0x00`. The bridge's default native-frame maximum is 256 bytes; its bounded decoder discards oversize/bad blocks until the next delimiter. Each child retains its own ID, secret, and boot ID. A separate upstream session is used per serial child. TLS ends at the bridge; the child authenticates using the same transcript proof across it.
